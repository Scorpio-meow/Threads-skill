一個技能，三種工作

問一句跟 Threads API 有關的事，技能就會自動啟用，再依你要的是程式、操作帳號還是網頁嵌入，換一套做法。

寫程式、查問題

沿用專案現有的語言和寫法（Node.js、Python、C#、Go 都行，沒有專案時用 Python），把文件規則直接寫進程式：token 從環境變數讀、發文走完整流程、送出前先在本機檢查、4xx 錯誤不盲目重試。

「幫我用 TypeScript 寫一個每天抓 Threads 貼文數據的排程，token 要能自動續期。」

直接操作你的帳號

用你的 token 發文、回覆、查數據、隱藏留言。先呼叫 GET /me 告訴你要操作哪個帳號；發文、刪文、隱藏留言之前，列出完整內文和每個參數，等你明確同意。只是查資料就不必確認。

「把我最新一篇貼文底下提到『加賴』的留言隱藏起來。」

把貼文嵌入網站

用 oEmbed 取得嵌入碼（2026 年 3 月起不需要 token），整頁只載入一次 embed.js，插入貼文後呼叫 instgrm.Embeds.process()。一頁放很多則時依序載入，失敗的換成連回原文的卡片。

「幫我做一面 60 則精選貼文的展示牆，並每週自動檢查哪些貼文已經被刪掉。」

長效 token 的一生th_refresh_token

0–24 h可以續期建議續期過期
發出第 1 天第 50 天第 60 天

發出未滿 24 小時：還不能續期

滿 24 小時、還沒過期：可以續期，換到新的 60 天

剩不到 10 天，或每週固定續一次（技能的建議）

過期後不能續期，只能請使用者重新授權

文件寫的：長效 token 約 60 天到期，發出滿 24 小時、還沒過期時才能續；新 token 和到期時間要一起存好。

發文

  • 2 步先建立 container，再發佈container ID 只用來查狀態和發佈，發佈後拿到的 media ID 才是貼文本身POST /me/threads_publish
  • 24 hcontainer 不發佈就過期狀態會變成 EXPIRED；API 沒有排程功能，要晚點發就晚點再建立status
  • 500內文字數上限emoji 依 UTF-8 位元組計算，大多數算 4，☕️ 算 6text
  • 5不重複的連結上限內文網址加 link_attachment 一起算，超過回 THREADS_API__LINK_LIMIT_EXCEEDEDlink_attachment
  • 2–20輪播的項目數圖片、影片可以混搭，每個項目都要帶 media_type，整組算一則貼文children
  • 1–25投票選項的字數只能用在純文字貼文；沒有題目欄位，也沒有設定投票時長的參數poll_attachment
  • 250每 24 小時能發的貼文數每個帳號滾動計算，輪播算一則threads_publishing_limit

搜尋

  • 100每頁最多筆數limit 預設 25；用 paging.cursors.after 翻頁，回應裡沒有 nextlimit
  • 2,200關鍵字搜尋次數，每 24 小時每位使用者跨所有 App 計算，沒有結果的查詢不算keyword_search
  • 100查公開帳號的粉絲門檻用戶名要完全一致、不加 @；權限核准前只查得到幾個 Meta 官方帳號profile_lookup

  • 1 h授權碼的效期只能用一次；callback 網址尾端的 #_ 要去掉code

  • 24 h發出滿 24 小時才能續期過期就不能續，只能請使用者重新授權th_refresh_token
  • 90 天權限授予的期限公開帳號續期會一起延長；私人帳號不能延長，每 90 天要重新授權data_access_expires_at

配額

  • 250發文，每 24 小時在 threads_publish 時計算quota_usage
  • 1,000回覆，每 24 小時查詢要另外有 threads_manage_replies 權限reply_quota_usage

  • 1,000oEmbed 請求，每小時頁面上載入嵌入沒有公開的上限，但載太多會被限流/oembed
  • 4,800App 層級呼叫數 × 曝光數每個 App 與使用者的組合，滾動 24 小時；曝光數至少算 10app-level

嵌入

  • 0oEmbed 需要的 tokenchangelog 寫明 2026-03-03 起不需要 token/oembed
  • 320–658maxwidth 的範圍超出範圍回 HTTP 500、code 100，這是參數錯誤，不要重試maxwidth
  • 3embed.js 同時載入的則數一則回報高度或 10 秒後才換下一則（2026-10 觀察）embed.js
  • 3.6 s大量嵌入時每則的間隔一則一則載入；連續失敗就暫停，60 秒起每次乘 1.5，最多 5 分鐘（practice）Embeds.process()
  • 24貼文已不存在的錯誤碼只有 code 24 才從清單移除，其他錯誤都當成暫時性問題code 24
  • 2CSP 要放行的地方script-src 和 frame-src 都要允許 https://www.threads.comContent-Security-Policy

除錯

  • 190token 無效或過期續期或重新授權；用 debug_token 看 token 的狀態和權限OAuthException
  • 24oEmbed 找不到貼文貼文已刪除，或帳號是私人、停用、年齡限制，或貼文限定地區Media Not Found
  • 429一次載入太多嵌入剩下的貼文停在純連結；依序載入，失敗的換成備援卡片HTTP 429
  • 5連結超過上限不重複網址超過 5 個，建立 container 時就會失敗LINK_LIMIT_EXCEEDED
  • -G官方範例裡不能照抄的 curlGET 請求用了 curl -F，會送出 multipart 本文；改成 curl -G --data-urlencodecurl
  • q地點搜尋的參數名稱教學寫 q、參考文件寫 query；技能先送 q，結果不對再試 querylocation_search

常見問題

要怎麼手動安裝？

把 threads-api 資料夾複製到工具讀取的技能資料夾，讓 SKILL.md 落在 <技能資料夾>/threads-api/SKILL.md。個人資料夾給這台電腦上的所有專案用；專案資料夾放在專案根目錄，可以 commit 給團隊一起用。

同時用 Codex、Gemini CLI、Copilot、Cursor 的話，放一份在 ~/.agents/skills/ 就能共用。~ 在 Windows 是使用者資料夾。工具沒偵測到新技能時，重新啟動一次即可。

在 Claude 應用程式怎麼用？
  1. 開啟程式碼執行：Free、Pro、Max 方案到 Settings > Capabilities 開啟「Code execution and file creation」；Team、Enterprise 方案由組織擁有者開啟它和「Skills」。
  2. 把 threads-api 資料夾單獨壓成 ZIP，最上層要是 threads-api/。GitHub 的 Download ZIP 是整個 repo，不能直接上傳。
  3. 到 Customize > Skills，按 + → Create skill → Upload a skill，上傳 ZIP。

App 的程式碼執行環境預設連不到 Threads API。在 App 裡代操作時，Claude 會把指令和參數準備好，交給你在自己的電腦上執行。

它會不會自己發文？

不會。發文、回覆、轉發、刪文、隱藏留言之前，它會在回覆裡列出帳號、完整內文、媒體網址和每個參數，等你明確同意。你說「直接發」，只代表同意你給的內容；它替你改過或選過的地方，還是會再問一次。只是查資料就不需要確認。

發文失敗時不會盲目重試。它會先查 container 的狀態：已經是 PUBLISHED 就代表發出去了，FINISHED 就發佈同一個 container，避免重複發文。

token 要放在哪裡？

設成環境變數 THREADS_ACCESS_TOKEN，或在專案資料夾的 .env 寫一行 THREADS_ACCESS_TOKEN=<你的 token>，並把 .env 加進 .gitignore。技能要求只透過環境變數把 token 交給要執行的指令，不寫進對話、程式或 commit。

# macOS／Linux，啟動 AI 工具前
export THREADS_ACCESS_TOKEN="<token>"
# Windows PowerShell
$env:THREADS_ACCESS_TOKEN="<token>"

還沒有 token，就直接問它「怎麼取得 Threads API 的 access token」。它會帶你建立 Meta App、把帳號加成 Threads 測試人員、走 OAuth 流程，再換成約 60 天的長效 token。

內容新到什麼時候？

整理自 Meta 官方文件，涵蓋到 2026-08-12 的 changelog。嵌入貼文的部分另外參考 2026 年 10 月實際讀取的 embed.js 程式碼和實測結果。之後的變動以官方 changelog 為準。

文件互相矛盾或沒寫清楚的地方，例如地點搜尋要用 q 還是 query、限時貼文加上不支援的功能時 API 會報錯還是直接忽略，技能會照實說明，不會自行假設。

有哪些已知限制？
  • 內建用戶端只在模擬的 API 上測過，還沒有對真實帳號實際發文。
  • 測試只在 Claude 上跑過；其他工具應該能照同樣的流程運作，但沒有實測。
  • 代操作需要工具能執行終端機指令，電腦上要有 Python 3.8 以上。
  • embed.js 的載入行為官方沒有文件，是 2026 年 10 月觀察到的，Meta 可能隨時改變。
  • 不涵蓋 Threads 廣告，那屬於 Marketing API。
怎麼參與貢獻？
  • 規則有誤或官方文件更新時，直接修改 threads-api/SKILL.md。文件沒寫、屬於工程經驗的建議，標成 practice。
  • 修改後用 Anthropic 的 skill-creator 照 evals/evals.json 重跑「有技能 vs 沒技能」，確認沒有退步，再更新 benchmark。
  • 發現新的易錯點，可以在 evals/evals.json 加一題，附上能逐條判定的檢查項目。
  • README 和 benchmark 摘要有繁體中文、英文、日文、韓文四個版本，修改時請一併更新。
