你

幫我發一則 Threads：「週末限定！新品手沖咖啡豆 9 折 ☕️ 詳情看這裡 https://example.com/sale」，附一個投票問大家喜歡「淺焙」還是「深焙」，然後設成 24 小時後自動消失的限時貼文。token 我已經放在環境變數 THREADS_ACCESS_TOKEN 了，直接幫我發。

Claude・有技能

還沒發出，也還沒呼叫任何 API。

Threads API 的限時貼文（is_ghost_post=true）只能是純文字，唯一能另外加的是文字防雷（spoiler），投票、GIF、連結預覽卡都不支援。我先在本地檢查（不呼叫 API），就被擋下了：ghost posts only support text spoilers, not poll_attachment。這兩個功能我不會擅自拿掉任何一個，請你決定：

方案 A｜限時貼文，不附投票

media_type=TEXT
text=週末限定！新品手沖咖啡豆 9 折 ☕️ 詳情看這裡 https://example.com/sale
is_ghost_post=true

長度 54／500（依規則 ☕️ 算 6），連結 1 個。

方案 B｜一般貼文＋投票

media_type=TEXT
text=週末限定！新品手沖咖啡豆 9 折 ☕️ 詳情看這裡 https://example.com/sale
poll_attachment={"option_a": "淺焙", "option_b": "深焙"}

現在是 10/14（三）上午 9:37。限時貼文如果現在發，大約 10/15（四）上午 9:37 就會封存，這個週末（10/17–18）完全看不到。

後面還有方案 C（拆成兩則）、網址是範例網域、投票沒有題目欄位等提醒，以及在你電腦上執行的指令。

Claude・沒技能

這則還沒發出去。有一個地方卡住，另外有幾件事要你決定。

你的三個要求沒辦法放進同一則。我不想自己默默拿掉其中一個，所以請你選：

  • A. 限時貼文、不附投票
  • B. 一般貼文＋投票（我推薦）
  • C. 分兩則發：促銷文案發限時貼文，投票另外發一則一般貼文

「不能附投票」是我對 Threads API 規則的理解。這次沒有 token，所以我沒辦法實際打 API 驗證。腳本的 ghost-poll 模式會先用不公開的方式試一次，API 拒絕就停下來，不會自己改發別的版本。

python3 post_threads.py --variant poll --url https://你的網址/sale

--variant 也可以換成 ghost（方案 A）或 ghost-poll（照原需求試）。

47 秒看完整個技能

同一個要求的兩種回答、三種工作、送出前的檢查，再到評測結果。影片是英文，有配樂。

一個技能，三種工作

問一句跟 Threads API 有關的事，技能就會自動啟用，再依你要的是程式、操作帳號還是網頁嵌入，換一套做法。

寫程式、查問題

沿用專案現有的語言和寫法（Node.js、Python、C#、Go 都行，沒有專案時用 Python），把文件規則直接寫進程式：token 從環境變數讀、發文走完整流程、送出前先在本機檢查、4xx 錯誤不盲目重試。

「幫我用 TypeScript 寫一個每天抓 Threads 貼文數據的排程，token 要能自動續期。」

直接操作你的帳號

用你的 token 發文、回覆、查數據、隱藏留言。先呼叫 GET /me 告訴你要操作哪個帳號；發文、刪文、隱藏留言之前，列出完整內文和每個參數，等你明確同意。只是查資料就不必確認。

「把我最新一篇貼文底下提到『加賴』的留言隱藏起來。」

把貼文嵌入網站

用 oEmbed 取得嵌入碼（2026 年 3 月起不需要 token），整頁只載入一次 embed.js，插入貼文後呼叫 instgrm.Embeds.process()。一頁放很多則時依序載入，失敗的換成連回原文的卡片。

「幫我做一面 60 則精選貼文的展示牆，並每週自動檢查哪些貼文已經被刪掉。」

沒裝技能時，錯在文件細節

以下都是評測裡發生過的：同一個模型沒裝技能時答錯，裝了技能就沒再犯。錯的多半不是程式，而是藏在文件細節和最近 changelog 裡的規則。

  • 查公開帳號，門檻是 100 位粉絲

    沒技能時：說 profile_lookup 只查得到粉絲 1,000 人以上的帳號，或完全沒提門檻。

    文件寫的：門檻在 2025 年 11 月已經降到 100。只查得到公開帳號，用戶名要完全一致、不加 @。

    GET /profile_lookup?username=…

    粉絲門檻，舊規則1,000
    粉絲門檻，2025 年 11 月起100

  • 巢狀回覆不能單獨隱藏

    沒技能時：先對巢狀回覆本身呼叫隱藏，失敗了才改處理上層留言。

    文件寫的：manage_reply 只對第一層留言有效，而且會連同底下整串一起隱藏。技能會先說明這個取捨，再讓你決定。

    會一起被隱藏

  • 翻頁要讀 cursors.after

    沒技能時：翻頁只跟著 paging.next 走。

    文件寫的：貼文列表的回應只有 cursors，沒有 next。只等 next 的程式，照文件的說法只會抓到第一頁。

    GET /me/threads?fields=id,text&limit=25

    {
  "data": [ … ],
  "paging": {
    "cursors": {
      "before": "QVFIUmFtN2Vx…",
      "after": "QVFIUkd3cDJ0…"
    }
  }
}  // 沒有 "next"

  • token 續期有條件

    沒技能時：續期前沒檢查 token 是否已發出滿 24 小時、而且還沒過期。

    文件寫的：長效 token 約 60 天到期，發出滿 24 小時、還沒過期時才能續；新 token 和到期時間要一起存好。

    長效 token 的一生th_refresh_token

    0–24 h可以續期建議續期過期
    發出第 1 天第 50 天第 60 天

    發出未滿 24 小時：還不能續期

    滿 24 小時、還沒過期：可以續期，換到新的 60 天

    剩不到 10 天，或每週固定續一次（技能的建議）

    過期後不能續期，只能請使用者重新授權

  • embed.js 會重新掃描頁面

    沒技能時：以為 embed.js 只在載入時掃描一次，於是把每則貼文各包進一個 iframe 頁面。

    技能寫的：用 innerHTML 塞進去的 <script> 不會執行。整頁載入一次 embed.js，插入貼文後呼叫 process() 就會重新掃描。這部分官方沒有文件，是 2026 年 10 月讀 embed.js 程式碼觀察到的。

    把貼文加進頁面embed.js

    wall.innerHTML += savedEmbedHtml;
    會掃描 
    wall.append(blockquote);
window.instgrm?.Embeds?.process();

    沒技能時：以為要先有 Meta App 和 token 才能準確檢查，改去爬 threads.com 的頁面。

官方文件在 2026-10-23 同步，涵蓋到 2026-08-18 的 changelog。標成 practice 的是工程建議，observed 是實測結果，其餘都出自 Meta 官方文件。下面挑出各節最常用到的數字。

發文

  • 2 步先建立 container，再發佈container ID 只用來查狀態和發佈，發佈後拿到的 media ID 才是貼文本身POST /me/threads_publish
  • 24 hcontainer 不發佈就過期狀態會變成 EXPIRED；API 沒有排程功能，要晚點發就晚點再建立status
  • 500內文字數上限emoji 依 UTF-8 位元組計算，大多數算 4，☕️ 算 6text
  • 5不重複的連結上限內文網址加 link_attachment 一起算，超過回 THREADS_API__LINK_LIMIT_EXCEEDEDlink_attachment
  • 2–20輪播的項目數圖片、影片可以混搭，每個項目都要帶 media_type，整組算一則貼文children
  • 1–25投票選項的字數只能用在純文字貼文；沒有題目欄位，也沒有設定投票時長的參數poll_attachment
  • 250每 24 小時能發的貼文數每個帳號滾動計算，輪播算一則threads_publishing_limit

搜尋

  • 100每頁最多筆數limit 預設 25；用 paging.cursors.after 翻頁，回應裡沒有 nextlimit
  • 2,200關鍵字搜尋次數，每 24 小時每位使用者跨所有 App 計算，沒有結果的查詢不算keyword_search
  • 100查公開帳號的粉絲門檻用戶名要完全一致、不加 @；權限核准前只查得到幾個 Meta 官方帳號profile_lookup

  • 500地點搜尋次數，每 24 小時沒有分頁；權限核准前只會回 Menlo Parklocation_search

回覆

  • 第 1 層只能隱藏第一層留言會連同底下整串一起隱藏，巢狀回覆不能單獨隱藏manage_reply
  • 1,000每 24 小時能發的回覆數回覆別人的貼文要有搜尋或提及權限，從那裡找到的貼文才能回reply_to_id
  • 全部conversation 一次攤平所有層在主貼文上呼叫；replies 只回直接回覆，有 has_replies 時要遞迴/conversation
  • 6hide_status 的值NOT_HUSHED、UNHUSHED、HIDDEN、COVERED、BLOCKED、RESTRICTEDhide_status
  • 審核回覆先等你核准建立貼文時加 enable_reply_approvals=true，限時貼文不能用manage_pending_reply

數據

  • 6單篇貼文的指標views、likes、replies、reposts、quotes、shares，都是累計值；要每日數字就每天存快照再相減/{media-id}/insights
  • 100粉絲分布的粉絲門檻每次只能帶一個 breakdown，不能帶 since、untilfollower_demographics
  • 2024-04-13since、until 最早的時間要用 Unix 時間戳，至少 1712991600；2024-06-01 之前的資料不保證threads_insights
  • 0轉發貼文的數據轉發會讀成 REPOST_FACADE，查數據只會回空清單REPOST_FACADE
  • 2不能帶日期區間的指標followers_count 和 follower_demographics，要和其他指標分開呼叫followers_count

授權

  • 1 h授權碼的效期只能用一次；callback 網址尾端的 #_ 要去掉code
  • 60 天長效 token 的效期短效 token 還有效時，在伺服器端換發th_exchange_token
  • 24 h發出滿 24 小時才能續期過期就不能續，只能請使用者重新授權th_refresh_token
  • 90 天權限授予的期限公開帳號續期會一起延長；私人帳號不能延長，每 90 天要重新授權data_access_expires_at
  • 11threads_* 權限App Review 通過前，只能用在 App 的 Threads 測試人員帳號（自己的帳號也要加入）threads_basic
  • 2 組App ID 和密鑰要用 Threads 那一組，不是 Facebook 那一組THREADS_APP_ID

配額

  • 250發文，每 24 小時在 threads_publish 時計算quota_usage
  • 1,000回覆，每 24 小時查詢要另外有 threads_manage_replies 權限reply_quota_usage
  • 100刪文，每 24 小時只能刪自己的貼文，刪除是永久的delete_quota_usage
  • 500地點搜尋，每 24 小時需要 threads_location_tagging 權限location_search_quota_usage
  • 1,000oEmbed 請求，每小時頁面上載入嵌入沒有公開的上限，但載太多會被限流/oembed
  • 4,800App 層級呼叫數 × 曝光數每個 App 與使用者的組合，滾動 24 小時；曝光數至少算 10app-level

嵌入

  • 0oEmbed 需要的 tokenchangelog 寫明 2026-03-03 起不需要 token/oembed
  • 320–658maxwidth 的範圍超出範圍回 HTTP 500、code 100，這是參數錯誤，不要重試maxwidth
  • 3embed.js 同時載入的則數一則回報高度或 10 秒後才換下一則（2026-10 觀察）embed.js
  • 3.6 s大量嵌入時每則的間隔一則一則載入；連續失敗就暫停，60 秒起每次乘 1.5，最多 5 分鐘（practice）Embeds.process()
  • 24貼文已不存在的錯誤碼只有 code 24 才從清單移除，其他錯誤都當成暫時性問題code 24
  • 2CSP 要放行的地方script-src 和 frame-src 都要允許 https://www.threads.comContent-Security-Policy

除錯

  • 190token 無效或過期續期或重新授權；用 debug_token 看 token 的狀態和權限OAuthException
  • 24oEmbed 找不到貼文貼文已刪除，或帳號是私人、停用、年齡限制，或貼文限定地區Media Not Found
  • 429一次載入太多嵌入剩下的貼文停在純連結；依序載入，失敗的換成備援卡片HTTP 429
  • 5連結超過上限不重複網址超過 5 個，建立 container 時就會失敗LINK_LIMIT_EXCEEDED
  • -G官方範例裡不能照抄的 curlGET 請求用了 curl -F，會送出 multipart 本文；改成 curl -G --data-urlencodecurl
  • q地點搜尋的參數名稱教學寫 q、參考文件寫 query；技能先送 q，結果不對再試 querylocation_search

在 Claude 應用程式怎麼用？
  1. 開啟程式碼執行：Pro、Max 方案到 Settings > Capabilities 開啟「Code execution and file creation」；Team、Enterprise 方案由組織擁有者開啟它和「Skills」。
  2. 把 threads-api 資料夾單獨壓成 ZIP，最上層要是 threads-api/。GitHub 的 Download ZIP 是整個 repo，不能直接上傳。
  3. 到 Customize > Skills，按 + → Create skill → Upload a skill，上傳 ZIP。介面如果是 Settings > Capabilities，就在 Skills 區塊按 Upload skill。

App 的程式碼執行環境預設連不到 Threads API。在 App 裡代操作時，Claude 會把指令和參數準備好，交給你在自己的電腦上執行。

它會不會自己發文？

不會。發文、回覆、轉發、刪文、隱藏留言之前，它會在回覆裡列出帳號、完整內文、媒體網址和每個參數，等你明確同意。你說「直接發」，只代表同意你給的內容；它替你改過或選過的地方，還是會再問一次。只是查資料就不需要確認。

發文失敗時不會盲目重試。它會先查 container 的狀態：已經是 PUBLISHED 就代表發出去了，FINISHED 就發佈同一個 container，避免重複發文。

token 要放在哪裡？

設成環境變數 THREADS_ACCESS_TOKEN，或在專案資料夾的 .env 寫一行 THREADS_ACCESS_TOKEN=<你的 token>，並把 .env 加進 .gitignore。技能要求只透過環境變數把 token 交給要執行的指令，不寫進對話、程式或 commit。

# macOS／Linux，啟動 AI 工具前
export THREADS_ACCESS_TOKEN="<token>"
# Windows PowerShell
$env:THREADS_ACCESS_TOKEN="<token>"

還沒有 token，就直接問它「怎麼取得 Threads API 的 access token」。它會帶你建立 Meta App、把帳號加成 Threads 測試人員、走 OAuth 流程，再換成約 60 天的長效 token。

內容新到什麼時候？

整理自 Meta 官方文件（2026-10-23 同步，涵蓋到 2026-08-18 的 changelog）。嵌入貼文的部分另外參考 2026 年 10 月實際讀取的 embed.js 程式碼、實測結果和兩個實際專案的經驗。之後的變動以官方 changelog 為準。

文件互相矛盾或沒寫清楚的地方，例如地點搜尋要用 q 還是 query、限時貼文加上不支援的功能時 API 會報錯還是直接忽略，技能會照實說明，不會自行假設。

有哪些已知限制？
  • 內建用戶端只在模擬的 API 上測過，還沒有對真實帳號實際發文。
  • 測試只在 Claude 上跑過；其他工具應該能照同樣的流程運作，但沒有實測。
  • 代操作需要工具能執行終端機指令，電腦上要有 Python 3.8 以上。
  • embed.js 的載入行為官方沒有文件，是 2026 年 10 月觀察到的，Meta 可能隨時改變。
  • 不涵蓋 Threads 廣告，那屬於 Marketing API。
