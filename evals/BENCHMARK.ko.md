# Benchmark 요약

[繁體中文](BENCHMARK.md) | [English](BENCHMARK.en.md) | [日本語](BENCHMARK.ja.md) | **한국어**

threads-api 스킬의 "스킬 있음 vs 스킬 없음" 3라운드 평가 요약입니다. 문제와 체크 항목은 [`evals.json`](evals.json)에, 실행별 항목 판정과 채점자가 첨부한 근거는 [`benchmark.json`](benchmark.json)에 있습니다.

## 평가 설정

| 항목 | 내용 |
|---|---|
| 답변 모델 | `claude-opus-5-5`(스킬 있음, 스킬 없음 두 설정 모두 같은 모델 사용) |
| 채점·분석 모델 | `claude-opus-5-5`, 채점자는 답변에 참여하지 않음 |
| 문제별·설정별 실행 횟수 | 1회 |
| 판정 방식 | 미리 정해 둔 체크 항목에 따라 하나씩 통과/불통과를 판정하고 근거(답변 원문, 코드 줄 번호, 모의 서버 실측 결과)를 첨부 |

| 라운드 | 시각(UTC) | 문제 |
|---|---|---|
| 1라운드 | 2026-10-13 07:07 | 1, 2, 3 |
| 2라운드 | 2026-10-13 08:14 | 2, 3, 4, 5 |
| 3라운드 | 2026-10-14 02:13 | 2, 3, 4, 5 |

라운드 사이마다 채점 의견을 반영해 스킬을 수정했습니다. 1번 문제는 양쪽 모두 만점이라 차이를 가릴 수 없어서 2라운드부터는 2–5번 문제를 사용했고, 3번 문제는 2라운드부터 체크 항목이 하나 늘었습니다.

## 평균 소요 시간과 토큰 사용량

| 라운드 | 스킬 있음 | 스킬 없음 |
|---|---|---|
| 1라운드 | 930초, 20.5만 토큰 | 840초, 17.7만 토큰 |
| 2라운드 | 599초, 16.4만 토큰 | 776초, 16.5만 토큰 |
| 3라운드 | 706초, 17.8만 토큰 | 963초, 18.9만 토큰 |

1라운드에서 스킬 있음 쪽이 더 느리고 사용량도 많았던 것은 스킬 자체를 읽는 데 약 1.1만 토큰이 들기 때문입니다. 2, 3라운드에서는 오히려 더 빨랐는데, 채점자는 시행착오가 줄었기 때문이라고 봤습니다. 문제별 소요 시간 차이가 매우 크므로(3라운드 스킬 없음 기준 298초에서 1,613초까지) 이 평균값은 참고용으로만 봐 주세요.

## 감점 항목

### 스킬 없음

| 문제 | 감점된 라운드 | 감점 원인 |
|---|---|---|
| 2 | 1, 2라운드 | 페이지네이션에서 `paging.next`만 따라가고 `paging.cursors.after`는 읽지 않았습니다. 문서에는 게시물 목록 응답에 `next`가 없다고 명시되어 있어, 문서대로라면 첫 페이지만 가져오게 됩니다. |
| 2 | 1, 2라운드 | 토큰 갱신 시 문서 규칙대로 확인하지 않았습니다. 가져온 토큰이 발급된 지 24시간이 지났는지, 아직 만료되지 않았는지 확인하지 않았습니다. |
| 3 | 세 라운드 모두 | 고스트 게시물에 투표를 붙일 수 없다고 명확히 말하지 않고 "안 될 수도 있다"고만 했으며, 두 기능을 함께 보내 보자는 선택지까지 제시했습니다. 문서에는 고스트 게시물이 지원하는 유일한 부가 기능이 텍스트 스포일러라고 명시되어 있습니다. |
| 3 | 세 라운드 모두 | 실제로 보낼 파라미터(`media_type`, `poll_attachment`, `is_ghost_post`)를 답변에 적지 않고 스크립트 안에만 넣어, 사용자가 확인하기 전에 볼 수 없었습니다. |
| 3 | 1, 2라운드 | `GET /me`를 호출했지만 토큰 검증에만 쓰고, 어느 계정으로 게시할지 먼저 알린 뒤 확인을 기다리지 않았습니다. 2라운드의 게시 스크립트는 게시 전에 `GET /me`를 아예 호출하지 않았습니다. |
| 4 | 2, 3라운드 | `profile_lookup`의 팔로워 기준을 예전 값인 1,000이라고 하거나 아예 언급하지 않았습니다. 2025년 11월부터 100으로 낮아졌습니다. |
| 5 | 2, 3라운드 | 중첩 답글 자체에 `manage_reply`를 먼저 호출하고, 실패한 뒤에야 상위 답글을 처리했습니다. 문서에는 중첩 답글을 단독으로 숨길 수 없다고 명시되어 있습니다. |

채점자의 결론은 이 감점이 거의 모두 코드를 못 짜서가 아니라 문서에 있는 규칙을 몰라서 생겼다는 것입니다. 2번 문제의 스킬 없는 버전이 3라운드에서 만점을 받은 것을 보면, 문제마다 한 번씩만 실행할 때는 한 번의 운이 평균값을 크게 흔들 수 있습니다.

### 스킬 있음

스킬 있음 답변은 어느 라운드에서도 감점된 항목이 없습니다.

### 감점은 없었지만 채점자가 지적한 문제

- **1라운드**: 스킬 있음 버전이 게시 후 게시물 URL을 조회하면서 `reply_audience` 필드까지 함께 요청했습니다. 이 필드는 `threads_read_replies` 권한이 필요해서, 권한이 없으면 성공한 게시가 실패한 것처럼 보일 수 있습니다. 게시 후에는 `permalink`만 조회하도록 스킬을 수정했습니다.
- **2라운드**: 채점자가 스킬 있음 버전의 답변을 통해 스킬 자체의 부정확한 표현 세 군데를 찾아냈습니다. `keyword_search`에 cursor 페이지네이션을 권장한 것(문서에는 cursor 파라미터가 없음), 비공개 계정의 90일 승인을 문서끼리 모순된다고 한 것(실제로는 문서가 일관되게 연장 불가라고 명시), "팔로워 관련 지표는 따로 호출"을 문서 규정처럼 쓴 것(실제로는 보수적인 방식일 뿐)입니다.
- **3라운드**: 채점자가 지나치게 단정한 표현 몇 군데를 지적했고, 이 역시 모두 스킬의 문구에서 비롯된 것이었습니다. 고스트 게시물에 링크 미리보기를 쓸 수 없다고 문서에 명시되어 있다고 한 것(문서는 텍스트 스포일러만 지원한다고만 함), API가 "반드시 거부한다"고 한 것(문서에는 API가 어떻게 반응하는지 나와 있지 않음), `profile_lookup`과 `profile_posts`의 각 1,000회 한도를 공유 한도로 취급한 것(문서에 공유 여부가 나와 있지 않음)입니다. 현재 SKILL.md는 이 세 가지 모두 문서가 불분명하다고 사실대로 설명하도록 수정되어 있습니다.

## 제한 사항

- 문제마다 설정별로 한 번씩만 실행했기 때문에 편차를 추정할 수 없으며, 수치는 경향 정도로만 봐 주세요.
- Claude에서만 평가했고, Agent Skills를 지원하는 다른 도구에서는 실제로 테스트하지 않았습니다.
- 테스트 중 API 호출은 모두 채점자가 띄운 모의 서버로 보냈고, 실제 Threads 계정으로 게시하지는 않았습니다.
- 원본 평가 보고서(실행별 전체 답변과 코드 포함)는 repo에 넣지 않았고, 여기에는 채점 데이터만 남겼습니다.
